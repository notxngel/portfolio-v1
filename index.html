05 / Process

How I build a project.

Version control from day one, previews at every stage and a repeatable deploy.

I define what the application needs to do, what data it handles and which services it depends on. That sets the stack, the project structure and a fixed price.

Semantic HTML, responsive CSS and JavaScript for interaction. Keyboard and screen reader accessible, and tested on mobile from the start.

Logic in Node.js, external APIs through asynchronous HTTP requests, authentication when it’s needed and environment variables kept out of the code.

Published on Netlify, Vercel, GitHub Pages or your own Linux server, with HTTPS and your domain. The repository and the code are yours.

07 / FAQ

Before we start

What technologies do you work with?

JavaScript across the stack: HTML, CSS and JS on the front end, Node.js on the server and Linux for infrastructure. Right now I’m adding React, Express and PostgreSQL.

Do you only do front end, or back end too?

Both. I can build just the interface if you already have a back end, or the full application with its server and integrations.

Where will my project be hosted?

Static sites go on Netlify, Vercel or GitHub Pages, which are free for most cases. Apps with a server go wherever fits the project best.

How long does it take?

A landing page usually takes [__] weeks and a web application [__] weeks. I’ll give you a specific date once we define the requirements.

Do I own the code?

Yes. When we finish, you get the full repository plus access to the hosting and the domain.

Do you work remotely?

Yes. I’m based in New Jersey and work with clients anywhere, in English and Spanish.
